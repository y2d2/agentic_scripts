# Task Plan: Mail-keeper workflow module (core)

**Purpose:** Implement the `mail-keeper` workflow in `agentic_scripts` — the runner that owns index-freshness verification, new-mail detection (cursors + processed log), the batched `mail-keeper` agent invocation, state, and guardrail verification — and register it in the shipped config.

## Objective

Create `src/agentic_scripts/workflows/mail_keeper.py` (module entry `create(config) -> Workflow`) so that, on each gate-open (or `--force`) run, the workflow verifies the notmuch index against the maildir (canary, report-and-defer on staleness), detects mail since per-folder cursors — first runs carry epoch-0 cursors, i.e. the user-confirmed **history backfill** (whole index, oldest-first) — builds a ≤10-message manifest (PII folder + own mail excluded BEFORE the agent), invokes the `mail-keeper` agent exactly once with the manifest, and — only on an `ok` agent result — advances cursors, appends the v1-schema processed log, and verifies the mail backup tree is byte-identical. Success: the high-level plan's runner-side acceptance (triage records, idempotent re-runs, PII exclusion, backup integrity, no-send) holds in hermetic tests, and the base smoke suite stays green with the workflow enabled (via Task 3b's env isolation).

## Tasks

### Task 1: Workflow module
- **Files:** `src/agentic_scripts/workflows/mail_keeper.py` (create)
- **Do:** Implement the module:
  - `create(config: Config) -> MailKeeper` where `MailKeeper` satisfies `Workflow` (`name = "mail-keeper"`).
  - Env/defaults (read at run time, env wins; document in the module docstring): `MAIL_INDEX_DB` → `/workspace/docker/mbsync/notmuch`; `MAIL_MAIL_ROOT` → `/workspace/docker/mbsync/backup`; `MAIL_OWNER_ADDRESS` → `yuri.durodie@vub.be`; `MAIL_PROCESSED_LOG` → `/workspace/Obsidian/config/email-processing-log.jsonl`. Constants: `MAX_BATCH = 10` (per-run manifest cap — user-confirmed history backfill runs 2026-10-21 make the cap the throughput knob; see global work plan Note 13), `PII_FOLDER = "INBOX/FU-Admin/PhD_applications"`, `EXCLUDED_FOLDERS = {"Sent Items", PII_FOLDER}` (and any folder under `PII_FOLDER`), `TRIAGE_FOLDERS` = the label list from Context (a folder is triage-eligible iff it is not in `EXCLUDED_FOLDERS` and not under the PII prefix).
  - `run(self, ctx) -> WorkflowResult` (never raises for business failures; wrap the body, map unexpected exceptions to `status="error"` with the exception text — programmer errors still surface in the run log):
    1. **Precheck:** `admin_repo = ctx.admin_repo`; if None → `skipped` ("admin_repo not configured"). Index dir missing, or `NotmuchReader` construction/first `count("")` raises → `skipped` ("notmuch index missing/unreadable: <err>") — no state writes.
    2. **Canary:** `res = canary.run_canaries(reader, mail_root, account)`; if `res["stale"]` → append to `actions` a stale note (total disk/index, reasons) — CONTINUE (defer, never lose); if `spot_check.ok` is False → append to `errors` (still continue unless the manifest is empty — see step 7).
    3. **State:** `st = ctx.state.load("mail-keeper")`; `cursors = st.get("cursors", {})`; `deferred = st.get("deferred", [])`. Absent cursor for a folder = `{"last_date": 0, "last_message_id": None}` — **epoch-0 cursors on first runs implement the user-confirmed history backfill** (global work plan Note 1): the whole index is the candidate set, triaged oldest-first, until cursors reach the present. On the very first run (no `bootstrapped_at` yet), compute `bootstrapped_at` (UTC ISO) + an `actions` line "first run: backfilling N indexed message(s) oldest-first (N = sum of `reader.count(q_folder(...))` over triage folders)". State is persisted ONLY on the no-new-mail path (step 5) or agent-`ok` (step 8d) — an agent failure writes no state at all (fresh re-detection next run is identical, so nothing is lost).
    4. **Detection** (per triage folder `f` with cursor `c`): `rows = reader.search(q_folder(account, f), limit=10**9)` — ONE search per folder, **no year prefix** (the backfill spans all years; INBOX ≈ 10k thread rows is fine on this local index, ~1 s). Keep rows with `row["timestamp"] > c["last_date"]`; order the kept rows **OLDEST-FIRST** (notmuch search default order is newest-first — reverse; test 1 below asserts the cursor lands on the folder's actual MAX timestamp, which also proves the order assumption). Walk the oldest-first threads, collecting each thread's `message_ids` fully (threads are small; collect a whole thread before the next) until ≥ `2 * MAX_BATCH` ids are collected (margin for the exclusions below); de-duplicate against previously-collected ids AND against the processed-log id set (read `MAIL_PROCESSED_LOG` once at run start: `{json.loads(line)["email_file"] for line in ...}` — tolerant of a missing file). For each collected id IN ORDER: `doc = reader.show(id)` (on `NotmuchError`: skip + log, continue); keep iff `doc["primary"]["timestamp"] > c["last_date"]` (strict) AND the From header does not contain the owner address (case-insensitive) AND the message's folder (derived from `filename[0]`) is not under the PII prefix (defense in depth — the folder loop already excludes it). The first `MAX_BATCH` kept ids = manifest; kept-but-over-cap ids → `deferred_new` (each stored as `{"message_id", "folder", "timestamp"}`). Also prepend the previous `deferred` entries (de-duplicated) before the fresh candidates so cap-truncated mail is never starved. A thread that qualifies only via a cross-folder reply (thread ts high, matched messages old) wastes a few shows and is filtered by the per-message ts check — harmless.
    5. **Manifest:** sort by `(timestamp, message_id)` ascending; if empty → NO agent call: save state (`deferred = deferred_new`), return `ok` with `items_found=0`, `actions=["no new mail (N candidates excluded: PII/own/processed)"]`.
    6. **Pre-walk:** `snapshot_before = _backup_snapshot(mail_root)` (see below) — taken right before the agent call.
    7. **Agent call:** `brief = _render_brief(run_id, manifest, owner)` (exact format below); `agent = ctx.runner.run(agent="mail-keeper", brief=brief, work_dir=ctx.admin_repo, title=f"mail-keeper {ctx.run_id}")`.
    8. **On `agent.status == "ok"`:** (a) parse triage classes from `agent.final_text`: best-effort regex over markdown table rows `^\|\s*(?P<id>\S+?)\s*\|[^|]*\|[^|]*\|(?P<class>noise|info|action|urgent)\s*\|` — build `{msg-id: class}`; unparseable → all `"mail-keeper"`. (b) Append processed-log records for EVERY manifest message (file `a` mode, `json.dumps(record, separators=(",", ":")) + "\n"`, UTF-8; create parent dir; `target_section` = parsed class or `"mail-keeper"`; `from` = the From header addresses as a list; `subject` = primary header Subject). (c) Advance cursors: per folder, `last_date` = max of the batch's timestamps in that folder, `last_message_id` = that newest id (folders with no batch members keep their cursor); `deferred = deferred_new`. (d) `ctx.state.save("mail-keeper", st_updated)`. (e) `snapshot_after = _backup_snapshot(mail_root)`; if `snapshot_before != snapshot_after` → append to `errors`: "mail backup tree changed during the run (guardrail trip)" — status becomes `error` (the agent is permission-denied from the backup; a trip means a config/denial gap). (f) Log the agent `final_text` in full at INFO (it is the result report); `actions` += summary lines ("agent ok (N messages, classes: ...)", "processed log: +N record(s)", "backup tree unchanged", "staleness: ..." if stale). Return `ok` (or `error` per (e)) with `items_found = len(manifest)`.
    9. **On `agent.status in {"error","timeout"}`:** NO cursor advance, NO processed-log append, `deferred` preserved; `errors` += `f"agent run {agent.status}: {agent.error} (duration {agent.duration_seconds:.0f}s)"` — the same batch is re-presented next run (agent dedup makes re-delivery safe); return `error`.
  - `_backup_snapshot(mail_root) -> dict[str, tuple[int, int]]` — Python `os.walk` (NEVER `find`) over `mail_root`: `{relpath: (size, mtime_ns)}` for every regular file (~13k entries, ~1–3 s); pure read-only.
  - `_render_brief(run_id, manifest, owner) -> str` — EXACT format (the skill parses by eye; keep it stable):
    ```
    mail-keeper run <run_id> — triage the new-mail manifest below (batch of N, date-ascending).
    Follow skill: mail-keeper (run, triage, vault fills, drafts, commit policy). Your final message must be the result report with the Triage table (| msg-id | folder | from | class | action taken |).

    MANIFEST (N message(s)):
    1. <message-id> | <folder> | <YYYY-MM-DD> | <From: name <addr>> | <Subject>
    2. ...
    ```
  - Keep all helper functions module-private; the only public surface is `create` + `MailKeeper` (the config import-check needs `create`).
- **Notes:** The workflow NEVER writes vault files, NEVER sends mail, NEVER runs `notmuch new`. The reader's `work_dir` = `ctx.sandbox_dir / "mail-keeper"` (created by the reader). `ctx.state.update` is load-mutate-save per key — prefer one `ctx.state.save(name, data)` per run (single atomic write). Timestamps in the manifest/brief are LOCAL calendar dates of the int-epoch `timestamp`.

## Notes

- **[Decision — backfill (user-confirmed 2026-10-21)]** First runs start with epoch-0 cursors → the whole index is triaged oldest-first in capped batches until the cursors reach the present (global work plan Notes 1, 3, 13). No "skip history" bootstrap exists in this design.
- **[Decision — cap edge]** Cap-truncated messages live in `state.deferred` and are re-injected next run (no loss at the cap); same-second arrivals below the strict-`>` cursor boundary are an accepted documented limitation (global work plan Note 3).
- **[Decision — steps-cap agent runs]** `status=="ok"` with a cap-summary final_text cannot be verified as complete → treat as partial: advance cursors ONLY for messages the Triage table explicitly lists with an action; unlisted manifest messages are pushed back into `deferred`. (If the Triage table is absent entirely → do NOT advance; return `error` "agent report unparseable — no cursor advance".)
- **[Risk — base smoke hermeticity]** Solved by Task 3b's additive env isolation (workflow → index-missing `skipped` in base smoke). There is therefore NO canary-walk latency in the base smoke and no short-circuit fallback to implement; the live-index canary cost (~1–3 s) only affects real gate-open/forced runs, which is acceptable.
- **[Assumption]** `notmuch search` default order is newest-first (test 1 asserts the cursor lands on the folder's actual MAX timestamp, which pins the assumption; if the order is oldest-first, the oldest-first walk in step 4 must NOT reverse — the test catches the mismatch).
- **[Note]** `from` addresses for the processed log: parse the primary `headers["From"]` string (RFC 5322 `Name <addr>`); store address(es) only (strip display names) — v1 stored `.get('email')` values.
