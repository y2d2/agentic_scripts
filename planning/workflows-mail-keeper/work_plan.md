# Work Plan: agentic_scripts — Mail-Keeper Workflow

**Purpose:** Orchestration work plan for `planning/workflows-mail-keeper/workflows-mail-keeper_plan.md` — ship the `mail-search` CLI over the maintained notmuch index, the mail-keeper workflow module (freshness canary, backfill-aware new-mail detection, manifest, batched agent invocation, processed log, guardrail verification), the real `email-routes.md`, and the hermetic smoke proving the end-to-end acceptance criteria with a fake agent.

## Objective

Turn the base system (scheduler + `NotmuchReader` + `AgentRunner`, all verified) into the working mail-keeper workflow of the high-level plan: with the gate open (or `--force`), one `mail-keeper` agent invocation per run triages the new-mail manifest, fills the `ARP_roadmap` vault with provenance-tagged notes/todos, writes local draft replies, and the vault commits with an `OC:` prefix to its current branch and pushes — idempotently, with the mail backup tree byte-identical before and after, PII folder excluded, and no mail ever sent. **User decision (2026-10-21, GATE 1): the history IS processed** — the first run starts a backfill, after which runs triage only mail newer than the cursors. **User revision (2026-10-23, Note 14, Task 5): the backfill is NEWEST-FIRST and capped at 1 year of history** — run 1 triages the 10 NEWEST messages of the past year; mail older than 1 year is out of scope; newly arriving mail is never starved during the backfill. Success = the high-level plan's acceptance criteria hold: canary-verified index freshness, a forced run produces triage records + (where warranted) provenance edits + todo + draft + pushed `OC:` commit, re-runs produce zero duplicates and advance the backfill, and gate-closed runs are no-ops.

3. **[Decision — cursor + detection algorithm]** Per-folder cursor = `{last_date: int epoch, last_message_id}` in `state/mail-keeper.json`. Per-run cost: 9 searches + ≤ ~20 shows + one processed-log read — seconds. Same-second arrivals below the strict-`>` boundary are a documented accepted limitation (mail arrives in mbsync batches minutes apart; the cap edge is covered by `deferred`).
