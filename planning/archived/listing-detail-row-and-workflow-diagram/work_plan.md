# Task Plan: plans.md per-plan sections + WORKFLOW mermaid

**Purpose:** Restructure the `plans.md` listing so each plan gets its own `###` section (6-col data table + a dedicated full-width details table), and document the engine pipeline with a mermaid graph.

## Objective

The `plans.md` listing in `/workspace/Python/autonomous_task_overview` renders one workflow-owned "detail row" per plan as a 6-cell row (`| — | — | **Goal:** … | **Tasks:** t1 · t2 | — | — |`) — 4 of its 6 columns are dead weight. True cell merging (colspan) is impossible in GFM pipe tables (research: `/workspace/Research/dev-tools/gfm-table-merged-cells.md`). The user's chosen design: **per plan, its own `###` heading + its own 6-column data-row table + a separate single-column "details" table** carrying the goal and one line per task. Success = the new structure is rendered by `render_listing`, still parses correctly (detail tables are never parsed as data rows), the full test suite is green, and the docs (WORKFLOW.md + README.md) match, including a new mermaid pipeline diagram.

## Context

- Engine repo: `/workspace/Python/autonomous_task_overview` (GitHub `y2d2/autonomous_task_overview`, currently on `main`, clean). ALL code/doc changes happen in this repo, on a new branch `feature/listing-detail-row` (create from current `main`, `git push -u origin feature/listing-detail-row`, `OC:`-prefixed commits, never merge to main — human gate).
- The listing lives at the repo root `plans.md` and is regenerated by the 30-min cron engine from `roadmap_dev.py:render_listing` — **never hand-edit it**; the next engine fire after merge re-renders it automatically (one large one-time diff is expected).
- `parse_listing` is deliberately defensive: rows whose cell count ≠ 6 are skipped; a 6-cell row whose priority cell fails `int()` is skipped. The new per-plan artifacts (`###` heading lines, 1-cell `| details |` header / `|---------|` separator / content lines, blank lines) all fall out of these existing guards **without parser behavior changes** — only docstrings describing the old detail-row format must be updated.
- User decisions (2026-11-25/26): merged colspan via full-HTML table rejected; per-plan two-table layout chosen; **skip the details table entirely when a plan has neither a goal nor task titles** (no `**Goal:** —` noise); "each task a new line within the details cell".
- Heading level: `#` = repo URL, `##` = branch (existing) → `###` = per plan is the natural next level. Heading text = the plan path (`row.plan`, the unique identity anchor per branch).

## Target format (byte contract for Task 1, mirrored by Task 2 docs)

Per repo (`# <repo_url>`), per branch (`## <branch>`), per plan:

```markdown
### planning/orbit-dmp/work_plan.md
| approval | priority | plan | title | state | remove |
|----------|----------|------|-------|-------|--------|
| ☐ | 1 | planning/orbit-dmp/work_plan.md | Task Plan: ORBIT DMP v0 | open | ☐ |

| details |
|---------|
| **Goal:** Build the DMP, table-first.<br>**Tasks:**<br>1 Skeleton & front matter<br>2 Master table 1 |
```

- `### <plan path>` heading line; then `_LISTING_HEADER` + `_LISTING_SEPARATOR` **repeated per plan** (each data row is its own table); then the data row exactly as today.
- Blank line, then (only when goal text or at least one task title exists) the 1-cell details table: header `| details |`, separator `|---------|`, content line `| **Goal:** <goal>[<br>**Tasks:**<br><task 1><br><task 2>…] |`. Missing part alone → `—` for that label only; **both empty → no details table at all**. Task lines are `<label> <title>` pairs, escaped with the existing `_escape_cell` (pipe → `\|`), joined by `<br>` — one task per line.
- Blocks are joined so there is exactly ONE blank line between any two plan blocks and before a following `##`/`#` heading; the file ends with a single trailing newline (no trailing blank line). Deterministic/byte-stable as today.
- Old-format rows (`| — | — | …`) are skipped by the existing parser guards (`—` fails `int()`), so live `plans.md` files in either format reconcile cleanly into the new one.
