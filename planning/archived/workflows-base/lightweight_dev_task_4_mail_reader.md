## Deviations from task spec
- **Test #9 (broken query surfaces) adapted to actual build behavior.** The task file specified: `reader.count("all:")` raises `NotmuchError` (exit ≠ 0, stderr tail in message). Empirical probing of this exact notmuch 0.38.3 build shows the broken forms (`all:`, `after:`, `before:`, `last:`, `field:*`) are **silent no-ops**: `notmuch count 'all:'` exits **0** and prints `0`; `notmuch search --format=json 'all:'` exits 0 with `[]`. They do *not* error. So the literal test would fail against reality. I implemented `test_broken_query_surfaces` to assert the true behavior (`reader.count("all:") == 0`, no exception) and documented the quirk in its docstring. The spec's actual intent — keep broken forms out of real queries — is fully preserved by the **builder refusal contract** (tests 8: `q_and()` empty → `NotmuchError`; `q_and("after:...")` / `q_and(..., "before:...")` → `NotmuchError`), which I implemented exactly as specified and did NOT weaken. This is a test-expectation correction, not a contract change.
- **`body_text` walks body parts recursively.** The task's spec text says "walk `body` parts in order," but the verified shape (and my live probe) shows HTML parts are nested under a multipart container's `content` list (`body[0]` is the `multipart/mixed` wrapper; the `text/html` leaf is at `body[0]["content"][0]`). A top-level-only walk would never see the HTML part and would return `(None, None)` instead of the required `(None, raw_path)`. I implemented a recursive `_iter_body_parts` so the HTML fallback works — this is what makes test #6 (the load-bearing contract the mail-keeper plan consumes) pass.
