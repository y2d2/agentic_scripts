# Task Plan: T4 — Phase 2/3 drain: continuous slots, job pipeline, outcomes

**Purpose:** Implement the in-process top-up drain (slots 1 by day / 2 by night, top-up on job end, let-finish on gate close, periodic re-scan) and the full job pipeline (worktree on `roadmap-dev/<id>-<attempt>`, headless `planner-enhanced` run with the 8 h budget, outcome routing: success → verify + commit + archive + **push the attempt branch** (NO PR — human opens it); questions → `questions.md` on the plan's branch; failure/timeout → `failure.md` on the plan's branch) with hermetic fake-runner tests.

## Objective

Replace the T3 drain stub with the reviewed plan's Phase 2/3 so that, with approved plans queued and an idling box, a slot is refilled the moment a job ends (day: one at a time; night: two concurrently), the user can re-prioritize between jobs, in-flight jobs finish when the gate closes, every outcome lands in the documented state + git form, and `success`/`failure` never auto-restart. **User decision 2026-11-21: the agent never creates PRs and never calls the GitHub API — success delivery is the pushed attempt branch; PR/merge is human-level verification.**

- **Drain loop (in-process, one `run()` holds the global lock):**
  ```
  top-up: while True:
      running = [jobs still active]
      if not running and no in-flight: break
      if not running:  # all done → re-read table, maybe start more
          re-scan+reconcile (fresh Phase 1 — see cadence below) → new rows/state
          if gate closed (live probe self._active_sessions() > 0): log "gate closed — no new starts"; break
          startable = select(rows, state)
          free = slots - 0
          start up to `free` jobs (top of the priority order) → break when none start
      else:            # jobs in flight
          if now - last_rescan >= poll_interval_minutes: re-scan+reconcile (keep listing live)
          wait for at least one job to finish (bounded poll, e.g. 15 s — join-with-timeout)
          for each finished job: route outcome (below), persist state atomically, cleanup
          loop back (top-up)
  ```
  - **Re-scan cadence** (reviewed-plan assumption, load-bearing): Phase-1 (scan+reconcile+push) runs (a) at drain start, (b) before every top-up that starts ≥1 job, (c) every `machine.poll_interval_minutes` (default 30) while jobs are in flight — so the listing stays live even though the drain holds the global lock. Implement as `_rescan(ctx)` calling the existing `_scan_and_reconcile` (it re-reads the REMOTE `plans.md`, so user edits between jobs are honored before each top-up).
  - **Gate close (let-finish):** live probe `self._active_sessions() > 0` → no NEW starts; in-flight jobs run to completion; drain ends when the last in-flight job finishes. (No preemption — rejected alternative.)
  - **Job start (per job, under the drain's state lock):** state entry → `pending` (`attempt += 1`, `started_at=now`, `pid` filled after spawn — see below), persisted atomically BEFORE spawn (a crash leaves a `pending` for the reaper). Worktree: `plan_worktree_dir`; drop a stale local `branch_name` first (oc_todo pattern), clean any leaked worktree, `worktree_add(clone, wt, branch_name, f"origin/{plan.branch}")`. Spawn: `runner.run(agent="planner-enhanced", brief=render_brief(run_id, plan, repo_url=…, attempt=entry["attempt"], timeout_minutes=settings.run_timeout_minutes, test_cmd=settings.test_commands.get(repo)), work_dir=wt, title=f"roadmap-dev {identity} ({run_id})", timeout_seconds=settings.run_timeout_minutes * 60)` inside a `threading.Thread` (2 at night). After spawn, store `pid` on the state entry (the fake runner in tests can record a sentinel pid; production: `AgentResult.pid` — capture via a small wrapper: run the runner call inside the thread and, immediately after `Popen`… the runner does not expose the pid until it returns. Resolution: the thread records `pid=None` in state until the result returns, then writes `result.pid` alongside the outcome (forensic value only — the reaper does not rely on pid liveness, it runs in a NEW process where ALL pending entries are orphans by construction).   - **Concurrency:** a single `threading.Lock` around state-doc mutation + `StateStore.save`; jobs never touch the state doc directly (they return outcome dicts; the drain serializes). `AgentRunner` runs are independent subprocesses — thread-safe per call.
- **Outcome routing (`_route_job(ctx, entry, plan, clone, wt, result: AgentResult, errors)`)** — runs in the drain thread (not the job thread):
  1. `result.status in {"error", "timeout"}` → **failure** with reason `f"agent {result.status}: {result.error or result.status}"` (covers the stray-headless-question exit-1 → documented auto-retry via re-arm).
  2. `result.status == "ok"`: `status_word = job_status_from_report(result.final_text)`; `None` → **failure** `no explicit status line in planner report`.
  3. `status_word == "questions"`: read `{plan.topic}/questions.md` from the worktree (missing → **failure** `status=questions but no questions.md in worktree`). Write it into a **diag worktree** (`diag_worktree_dir`, created on the LOCAL branch named exactly `plan.branch` from `origin/{plan.branch}` — `worktree_add(clone, diag_wt, plan.branch, f"origin/{plan.branch}")` after dropping any stale local `plan.branch`; a local branch sharing the remote-tracking name is legal), commit `diag_commit_message(identity, "questions", run_id)` (oc_todo idempotent `commit`), `push(diag_wt, plan.branch)` (non-ff → fetch + reapply once → give up: failure `questions.md push failed`), remove diag worktree (finally). → state `review` + `force_unapproved={identity}` reconcile pass (the ONE sanctioned approval removal; log `unapproved <id> (questions raised)`) + listing push.
  4. `status_word == "failure"`: same diag path with a `failure.md` written into the diag worktree (content = `result.final_text` — the planner's report, including its Blockers) → state `failure` (+`last_error` from the report's blockers section, truncated to 200 chars).
  5. `status_word == "success"`:
     a. **Tests gate** (when `settings.test_commands.get(repo)` is set): run the command in the worktree via `subprocess.run(cmd, shell=True, cwd=wt, capture_output=True, text=True, timeout=600)` — non-zero exit or timeout → **failure** `tests failed: <stderr tail 1000 chars>` (no commit, no push of the attempt branch? — the worktree is cleaned in finally; state `failure`). Not configured → skip (log note `no test command for <repo> — tests gate skipped`).
     b. **Non-empty diff gate:** `git.add(wt)`; `created = git.commit(wt, render_pr_title(plan))`; `created is False` → **failure** `agent made no changes — nothing to commit`.
     c. **Archive:** `git.mv(wt, plan.topic, f"planning/archived/{plan.topic.split('/')[-1]}")` — note: `plan.topic` = the plan folder (e.g. `planning/orbit-sim`); destination `planning/archived/orbit-sim`; `git.add(wt)`; `git.commit(wt, f"OC: roadmap-dev: archive plan {identity} (run {run_id})")` (False → still fine: nothing moved? that would mean the mv produced no diff — treat as failure `archive produced no commit`); record `commit_sha = git.rev_parse(wt, "HEAD")`.
     d. **Push** the attempt branch (`upstream=True`); on `GitError` → **failure** `push failed: …` (branch exists locally; forensics; state `failure`).
     e. **(delivery is the pushed branch — NO PR, NO GitHub API):** after the push succeeds, state `success` with `branch_name=roadmap-dev/<id>-<attempt>` + `commit_sha` set; log `pushed branch roadmap-dev/<id>-<attempt> for <repo> @ <branch> (<identity>) — human opens the PR`. The attempt branch carries the implementation + archived plan folder; the human verifies/merges (user decision 2026-11-21).

## Notes

- **[Assumption] `pid` forensic only:** the reaper (run start, new process) treats ALL `pending` entries as orphans — pid liveness is NOT consulted (document in the reaper docstring when T4 touches it — it does not need to).
- **[Assumption] 600 s test-command timeout** in the worktree is a reasonable default; it is NOT configurable in this task (a follow-up could add `roadmap_prompts.test_timeout_seconds`).
- **[Risk → guardrail] A `questions.md` the user edited on the branch is re-read by the agent on the next attempt** (the worktree is cut from `origin/<branch>` which carries it) — the brief tells the planner to read it; do not strip it in the runner.
- **[Note] Drain wall-clock:** there is no overall drain budget — only the per-job 480 min timeout (plan decision: `max_attempts`-style caps deliberately absent).
- **[Note] Every state mutation in the drain goes through the single lock + atomic save** — copy the discipline from T3's Phase 1; `WorkflowResult.errors` must name repo/identity so the operator can act.
- **[Note] Log lines** follow the run-log house style (`WORKFLOW roadmap-dev status=… …` is emitted by the scheduler; the workflow logs `INFO` one-liners like `drain start slots=2 startable=3` / `job finished <id> status=success duration=…s` / `top-up: starting <id> (slot 2/2)`).
